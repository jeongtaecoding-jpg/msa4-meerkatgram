# 비전공자를 위한 Meerkatgram 동작 흐름 안내서

웹 애플리케이션(Meerkatgram)이 사용자 요청을 받아 처리하는 과정을 비유 없이 핵심 개념 위주로 깔끔하게 설명합니다.

## 1. 프론트엔드와 백엔드의 역할 분리
- **프론트엔드 (사용자 화면)**: 사용자가 직접 조작하고 보는 앱/웹 화면입니다. 버튼 클릭, 글 작성 등의 동작을 통해 서버에 필요한 데이터를 요청합니다.
- **백엔드 (서버 및 데이터 처리)**: 눈에 보이지 않는 곳에서 데이터베이스를 관리하고 비즈니스 규칙에 맞게 데이터를 처리하는 시스템입니다.

## 2. 전체 데이터 처리 6단계 흐름

### 1단계: 사용자 요청 (Request)
- 사용자가 "게시글 목록 보기"를 클릭하면 프론트엔드는 백엔드 서버의 특정 주소(예: `/api/posts`)로 데이터를 보내달라고 요청합니다.

### 2단계: 인증 및 권한 확인 (Security & JWT)
- 서버는 가장 먼저 이 요청을 보낸 사람이 정상적으로 가입된 사용자인지 확인합니다.
- 로그인할 때 발급받은 **JWT(JSON Web Token)**라는 암호화된 인증 정보를 검사하여, 권한이 있는 안전한 요청만 내부 시스템으로 통과시킵니다.

### 3단계: 요청 접수 및 검증 (Controller 계층)
- **Controller**는 클라이언트(프론트엔드)의 요청을 가장 먼저 받아내는 최초의 진입점입니다.
- 사용자가 보낸 데이터가 올바른 형식인지(예: 숫자가 들어가야 할 곳에 문자가 들어오지 않았는지, 필수 값이 누락되지 않았는지) 일차적인 유효성 검사를 수행합니다.

### 4단계: 핵심 업무 및 데이터 가공 (Service 계층)
- **Service**는 애플리케이션의 핵심 비즈니스 로직(업무 규칙)을 담당합니다.
- 게시글을 등록할 때 사용자의 정보를 연결하고, 파일이 있다면 파일 업로드 처리를 진행하는 등 복잡한 데이터 가공 로직과 작업 순서를 조율합니다.

### 5단계: 데이터베이스 접근 및 영구 저장 (Repository 계층 & Database)
- **Repository**는 실제 데이터베이스(MySQL)와 소통하여 데이터를 넣고 빼는 역할을 전담합니다.
- Service 계층의 지시를 받아 데이터베이스에서 정보를 찾아오거나 가공된 데이터를 데이터베이스에 영구적으로 저장합니다.
- 이때 데이터베이스 테이블의 정보를 자바 코드 내에서 다루기 위해 사용하는 객체를 **Entity(엔티티)**라고 부릅니다.

### 6단계: 응답 반환 (Response)
- 처리가 완료되면 Service는 그 결과를 다시 Controller로 전달합니다.
- Controller는 클라이언트가 화면을 그리는 데 필요한 최종 형태(DTO: Data Transfer Object)로 데이터를 다듬어 최종 응답(Response)을 반환합니다.
- 이 응답을 받은 프론트엔드는 화면에 데이터를 뿌려주어 사용자가 결과를 볼 수 있게 합니다.

## 요약
- **전체 흐름**: 사용자 요청 ➡️ 보안 인증(JWT) ➡️ Controller(요청 검증) ➡️ Service(비즈니스 가공) ➡️ Repository(데이터 입출력) ➡️ Database ➡️ 프론트엔드로 응답 반환
- 이렇게 계층(레이어)을 나누어 각자 맡은 역할만 수행하도록 설계하면, 코드가 엉키지 않고 유지보수가 쉬워집니다.
